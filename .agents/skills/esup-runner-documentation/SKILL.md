# Esup-Runner documentation

- Read the affected section and comparable documentation before writing.
  Match their terminology, structure and level of detail; do not add
  precision beyond comparable existing content unless explicitly requested.
- Write in English. Use short, direct sentences and familiar vocabulary.
  Keep only information needed to understand, configure or operate the feature.
- Prefer updating the existing reference page. Link to existing explanations
  instead of repeating them. Create a page only when no suitable one exists.
- Verify commands, parameters, defaults and behavior against current source.
  Preserve necessary prerequisites, operational limits and upgrade actions.
- Keep changes within scope. Do not rewrite neighboring sections or published
  changelog history without a request.
- For changelogs, follow existing categories under Unreleased. Prefer one short
  bullet per meaningful change, grouping related details. Describe the practical
  effect; omit implementation inventories and test reports. Keep required upgrade
  actions explicit and link to documentation for procedures.
- Before finishing, remove repetition, filler and examples that add no useful
  information. Prefer the shortest wording that remains clear and accurate.
